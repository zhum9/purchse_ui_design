## 1 方案结论与阅读方式

本期做成一套能连续处理采购准备、订单承诺、履约事实与异常恢复的采购执行产品。保留现有 React、Ant Design、订单行驱动、统一履约工作台和 SAP 适配边界；补齐来源分配、统一订单编制、审批与版本、订单交付安排、履约账及反向处理。

这是一份待评审的设计交付，不表示页面、接口或数据库已经实现。没有修改业务代码、发布线上版本或建立数据库。先看第 2～5 节的范围与业务规则，再看第 7～9 节的页面设计，最后结合数据库附册评审数据关系。

### 1.1 设计依据与优先级

1. 本次用户要求优先：先做扎实核心，暂缓外围闭环和产品扩展。

4. 原始两份产品 DOCX 和此前整体评审作为背景。此前 V2 草案范围更广；本文件明确收窄本期范围，不自动修改旧文档中的架构约束。
5. `docs/PROCUREMENT_EXECUTION_DESIGN.md` 当前不存在。本方案使用独立文件名，避免把新评审稿伪装成既有已批准规范。

## 2 本期范围和不做的内容

| 范围 | 本期实际交付能力 | 边界 |
| --- | --- | --- |
| 我的工作 | 个人待办、审批、补充资料、交期提醒、异常任务 | 不做管理驾驶舱或独立消息平台 |
| 采购需求 | 创建、草稿、提交、审批、调整、关闭未安排部分、追踪采购覆盖 | 不计算库存净需求、MRP 或年度预算 |
| 需求池与采购计划 | 按明细筛选、部分分配、合并预览、独立计划、执行采购计划调整 | 不做年度战略规划、预算编制或跨法人交易 |
| 采购订单 | 多入口统一编制、价税金额、交付安排、审批、正式版本、受控变更 | 不建设询比价、招投标、合同签署模块 |
| 订单交付信息（归入采购订单） | 约定交期、分批数量和地点、未交量、临期/逾期提示；可选预计到货和延期备注 | 不建设独立催交工作台、供应商确认流程、账号、门户、EDI 或 ASN 模块 |
| 统一采购履约 | 库存/消耗性货物、无编码货物、服务验收、限额执行；草稿与正式记录 | 不建设独立 WMS、专业 QMS、工程里程碑计量 |
| 退货与更正 | 部分退货、收货冲销、退货冲销、服务验收更正、短交关闭 | 不建设索赔结算、维修工单、退款与付款执行 |
| 单据追溯与业务异常 | 来源明细、分配量、版本、执行及反向单据、责任人和处置结果 | 不用一个时间线代替所有关系和审计 |
| SAP 集成 | 正式 PO 同步、执行任务、未知核对、凭证关联、业务一致性核对 | “SAP 业务核对”不是供应商财务对账 |
| 执行配置与基础权限 | 场景识别、字段、有限采购策略、容差、简单审批规则、发布版本 | 不做通用低代码、任意脚本或完整 BPMN 设计器 |

本期不建设：供应商发送/回复/接受/拒绝流程及独立确认状态、供应商全生命周期、寻源定标、合同管理、预算控制、库存供应匹配、专业质量管理、发票与付款协同、质保台账、采购绩效和支出分析、进口/寄售/委外等行业扩展。

### 2.1 暂缓外围能力时仍须保留的安全边界

- 供应商、组织、单位、地点等使用最小参考目录，可由种子数据或外部导入提供；本期不做供应商准入流程。正式订单必须选有效目录记录，不能拿任意文本冒充 SAP 供应商。
- 合同、定标结果只保存外部编号、行、版本、摘要和证据，不生成本地合同。若当前采购策略要求合同依据，则必须有可核验引用；没有接口时可按允许的人工核验流程登记，不能伪造“已实时核验”。
- 发票、库存耗用等后续依赖不在本期展开。涉及冲销时，由适配器给出允许、禁止或未知；未知时阻断该危险动作，不假设无依赖。
- GitHub Pages 仍可发布浏览器本地原型；数据库是后端落地设计。Pages 不能直接连接数据库，多人共享业务数据必须部署服务端。

## 3 核心概念和可选路径

### 3.1 业务对象

| 对象 | 业务含义 | 本期关键约束 |
| --- | --- | --- |
| 需求单/行 | 谁需要什么、用途、需要量/金额和时间 | 建议供应商可空；估算不等于成交价 |
| 执行采购计划/行 | 谁来买、如何组织、何时下单和预计交付 | 可以汇总需求，也可独立创建；独立部分说明依据 |
| 订单/行 | 向确定的交易对方购买什么、多少、按什么条件 | 一单一个法人、供应商及币种；同单允许混合履约场景 |
| 交付安排 | 订单行如何分批、分地点履约 | 正式约定交期与可选内部预计到货分开；预计值不构成供应商承诺 |
| 执行单据 | 一次收货、验收、限额确认或反向处理 | 至少关联 PO + Item；必要时关联交付安排和原执行行 |
| 来源分配 | 本次订单或计划使用某个来源多少授权量 | 支持多对多；不可通过改累计值绕过控制 |
| 业务依据引用 | 合同、定标或其他外部凭据 | 只读引用，不默认扣减外部合同额度 |

### 3.2 本期支持的路径

| 路径 | 典型情形 | UI 入口 |
| --- | --- | --- |
| 需求 → 计划 → 订单 | 集中组织、多次转单 | 需求池 → 编制计划 → 编制订单 |
| 需求 → 订单 | 不需要单独计划的普通或临时采购 | 需求池 → 直接编制订单 |
| 独立计划 → 订单 | 有采购安排但没有明确需求单 | 计划列表 → 新建计划 |
| 直接订单 | 允许直接采购的业务 | 订单列表 → 新建订单 |
| 外部合同/寻源结果引用 → 订单 | 已在外部确定商业依据 | 订单编制 → 添加商业依据 |
| 外部 SAP 正式订单 → 履约 | 订单由 ERP 创建 | 同步后进入订单列表与履约工作台 |

需求、计划、合同均不是全局必经节点。路径能否采用取决于适用的采购策略和权限。绕过计划不等于绕过授权；自动审批也必须留下命中规则和执行记录。

首期每张需求、计划和订单均限定单法人。需求池可以查看有权限的多家公司，但生成时自动拆成不同单据并说明原因。集团统筹可跨单据查看，不在首期隐含支持跨法人采购结算。

### 3.3 采购分类不再混成一个枚举

| 维度 | 本期值 | 对页面的影响 |
| --- | --- | --- |
| 采购对象 | GOODS / SERVICE | 收货或服务验收 |
| 库存处理 | STOCK / NON_STOCK / NOT_APPLICABLE | 是否需要工厂、库存地点、批次 |
| 标识方式 | CODED / FREE_TEXT | 有编码只读展示；自由描述不要求物料号 |
| 计价方式 | UNIT_PRICE / FIXED_AMOUNT / LIMIT | 数量单价、固定金额或预计值与上限 |
| 执行控制 | QUANTITY / AMOUNT / QUANTITY_AMOUNT / LIMIT | 校验数量、金额或两者 |

保留现有 MAT_STOCK、MAT_CONSUME、MAT_FREE、SERVICE、SERVICE_LIMIT 作为兼容的执行场景编码，由上述属性和发布规则识别。不是开放所有维度的任意组合：只启用有表单、校验、反向处理和适配支持的预置组合。资产、寄售、外协、里程碑等未支持的行显示“待适配”，不得退化成普通收货。

| B02 | 草稿拟分配不占用；提交占用；批准确认；驳回/撤回释放 | 分开显示已确认、审批占用、当前可分配 |
| B03 | 需求经计划转订单，只扣计划可转量，不再次扣需求 | 上游追溯不等于再次消耗 |
| B04 | 同一来源并发提交必须服务端原子校验 | 冲突保留输入，指出哪一行余额变化 |
| B05 | 建议供应商可不采用；正式供应商必须有效 | 若有合同/定标约束，展示真实约束来源 |
| B06 | 估价缺失不是 0；下单必须确认适用商业条件 | 显示待定价，免费需明确原因 |
| B07 | 数量、金额、预计金额、最高限额分别存储 | 12 个月不能变成 12 元 |
| B08 | 本期不新增供应商回复作为执行前置 | 审批、订单生效及 SAP 释放照常校验；不显示虚构的供应商已接受状态 |
| B09 | 正式订单变更需新版本，受影响行暂停执行 | 未获权威确认不切换正式版本 |
| B10 | 业务事实和 SAP 过账分别记录 | “收货已确认，SAP 待处理”不称全部成功 |

| B12 | 退货不是冲销；退货后是否补货须明确 | 不补货不自动释放来源、不自动创建退款 |
| B13 | 未知 SAP 状态先核对，不直接重试 | 核对可能成功、明确未执行、仍未知或不一致 |

| B15 | 混合单位不能汇总数量，跨币种不能直接加金额 | 摘要显示行数；金额按币种分组 |
| B16 | 规则版本随单据冻结，最新余额和禁用状态仍实时校验 | 历史可解释，不因旧规则放过新风险 |
| B17 | 关闭履约不代表结算完成 | UI 使用“履约关闭”，不使用“采购全部结清” |

### 4.1 来源数量和估算口径

可分配量 = 当前授权量 − 有效确认分配 − 审批中占用 − 已关闭不再采购量。

需求 → 计划使用需求余额；计划 → 订单使用计划余额；需求 → 订单使用需求余额。已分配给计划的那部分需求，不能同时用于直接下单。要改走直接订单，先释放尚无下游的计划分配。

计划行合并多个需求时保留每个来源量和估价。订单部分转出时明确使用各来源多少，不采用无法解释的随机或隐式先进先出。可建议按需求日期优先分配，采购员确认后冻结。

订单的实际成交金额与来源估算分开。数量型来源控制数量，改价走价格差异规则；金额型来源控制实际授权承诺金额，超出授权必须先调整上游或取得独立追加授权。不能把低估算分配值用于掩盖更高成交承诺。

### 4.2 本期金额模型

- 单张订单一种币种；首期原型预置 CNY，不硬编码数据库只允许 CNY。暂未适配的币种明确禁用。
- 单价明确含税/未税、计价单位和计价基数。例如 820 元/100 件，不显示成 820 元/件。
- 货物及按量服务：订购量按已确认换算关系转计价量，再计算行金额。
- 固定总价服务：维护约定金额，工作量可作为说明；不得强制虚构“1 件”。
- 限额服务：预计金额和最高限额同一税口径、同一币种。预计金额是预期，不代表必须支付；上限是约束，不是订单实际支出。
- 首期支持单一税率/税码的行级计算；复杂税制、跨币种、复杂费用分摊暂不启用。若外部订单有这些条件，保存权威金额并只读展示，不用简单公式覆盖。
- 金额使用十进制运算；未知税不能默认为免税。服务总额、数量、限额的条件必填见第 8 节。

## 5 角色和状态

### 5.1 角色矩阵

| 角色 | 主要权限 | 数据范围/限制 |
| --- | --- | --- |
| 需求人 | 新建、修改本人草稿、提交、跟踪、发起需求调整 | 本人或授权部门；不能直接批准 |
| 采购员/计划员 | 分配需求、编制计划/订单、维护可选交付备注、发起变更 | 授权法人、采购组织及采购组 |
| 审批人 | 审批分配给自己的当前版本任务 | 默认禁止自审批；代理保留实际身份 |
| 收货员 | 收货、查看执行、发起退货/冲销申请 | 授权工厂、地点；价格可按策略隐藏 |
| 服务验收人 | 验收成果、工作量/金额、发起验收更正 | 授权业务归属及订单行 |
| 采购主管 | 异常分派、变更审批、短交关闭审批 | 不因主管身份自动获得技术报文权限 |
| 集成运维 | 核对、查看脱敏日志、执行允许的恢复动作 | 不直接修改业务量或冒充审批人 |
| 配置管理员 | 编辑、预览、发布规则，维护角色授权 | 修改配置不等于获得采购操作权限 |

菜单、路由、动作、组织数据范围和敏感字段分别校验。无权限的业务数据不得先完整返回前端再隐藏。跨模块链接也重新授权。

### 5.2 独立状态维度

| 状态维度 | 本期语义 |
| --- | --- |
| 单据生命周期 | DRAFT 草稿 / ACTIVE 生效 / CLOSED 已关闭 / CANCELLED 已取消 |
| 版本状态 | WORKING 编制 / SUBMITTED 已提交 / AUTHORIZED 已授权 / EFFECTIVE 已生效 / SUPERSEDED 历史版本 / REJECTED 驳回 / WITHDRAWN 撤回 |
| 审批状态 | NOT_SUBMITTED / PENDING / APPROVED / REJECTED / NOT_REQUIRED；免审必须由策略产生 |
| 来源覆盖 | NONE / PARTIAL / FULL；审批中占用另外显示 |
| 履约进度 | OPEN / PARTIAL / COMPLETE；冻结和履约关闭另有标志 |
| SAP 任务 | WAITING / PROCESSING / SUCCESS / FAILED / UNKNOWN |
| 异常任务 | OPEN / IN_PROGRESS / WAITING_EXTERNAL / RESOLVED / CLOSED |

超期是日期风险，不覆盖“部分执行”。订单发生变更时，顶部同时显示“正式 V1”和“变更 V2 审批中”，不能将整张仍有效订单显示成草稿。

### 5.3 关键动作的状态结果

| 动作 | 前提 | 原子结果 | 后续失败的处理 |
| --- | --- | --- | --- |
| 保存草稿 | 有编辑权限；数据类型合法 | 保存当前工作版本，不占来源 | 返回保留输入；可恢复草稿 |
| 提交需求/计划/订单 | 完整业务校验；版本未过期 | 冻结提交内容；需来源时占用；创建审批任务 | 提交超时查询原请求，不重复提交 |
| 批准计划/订单 | 当前审批任务有效 | 记录授权；来源占用转确认 | 订单 ERP 失败不释放承诺，进入异常 |
| ERP 确认订单 | 匹配请求、版本和权威结果 | 切换正式版本，保留旧版 | UNKNOWN 暂不切换，先核对 |
| 确认收货/验收 | 当前正式行可执行；余额允许 | 写执行事实和正向事件；生成集成任务 | SAP 失败仍保留已确认事实和数量 |
| 提交退货/冲销 | 原记录有效；依赖检查通过 | 占用原记录可反向量；审批/ERP 处理 | 未核实成功前不释放可收余额 |
| 取消未执行部分 | 明确来源去向；权威确认 | 正式变更及对应分配释放/关闭 | 请求未知时维持原承诺 |

| 我的工作 | `/work/tasks`；任务详情 `/work/tasks/:id` | 新增，共用各业务操作，不复制业务编辑器 |

| 采购准备 | `/planning/aggregation` | 沿用路径，标题调整为“需求池与汇总” |
| 采购准备 | `/planning/plans`；`/planning/plans/new`；`/planning/plans/:id`；`/:id/edit` | 保留列表详情，补独立编制 |
| 采购订单 | `/purchase-orders`；`/purchase-orders/new`；`/purchase-orders/:id`；`/:id/edit`；`/:id/change` | 复用统一编辑器，来源通过查询参数/服务端草稿加载 |
| 采购履约 | `/fulfillment/workbench`；`/fulfillment/records`；`/fulfillment/records/:id`；`/fulfillment/service/:itemId` | 保留现有入口，补正式记录详情 |
| 退货与更正 | `/returns`；`/corrections/:id` | 保留原入口，Tabs 区分退货、冲销、服务更正 |
| 异常处理 | `/exceptions`；`/exceptions/:id` | 新增业务异常；不复制集成日志 |
| SAP 集成 | `/sap/monitor`；`/sap/reconciliation` | 保留；后者标题明确为“SAP 业务一致性核对” |
| 执行配置 | `/settings/execution-scenarios`；`/settings/field-rules`；`/settings/procurement-policies` | 前两项职责分开；新增有限策略配置 |

新建和静态子路径优先匹配，避免 `new` 被当成订单 ID。交付信息只作为订单详情子区域，不新增独立路由或菜单。旧路径维持重定向或功能兼容。首次默认首页可按角色配置；保留现有履约工作台书签。

## 7 页面详细设计

### P01 我的工作和审批详情

页面类型：任务列表＋独立详情。快速筛选为待我处理、我发起、我已处理；任务类型包括审批、补充资料、交期提醒、待验收、异常处置；交期提醒由约定日期和未履约量产生，不创建等待供应商回复的任务。表格显示任务、业务单号、摘要、责任人、到期时间、等待原因和主操作。

审批详情上方显示提交版本、提交人、授权范围和影响摘要；中部复用对应单据只读详情；右侧显示审批链及意见。订单变更审批必须有前后对比，不能只让审批人看新值。

主操作为批准/驳回；驳回原因必填。已过期版本任务只读并可跳到当前任务。待办链接不直接批准，用户必须查看上下文。暂不做批量审批、批量冲销或通用流程画布。

### P02 采购需求列表和详情

页面类型：列表、详情。列表顺序为标题与新建、状态 Tabs、查询、表格、分页。常用查询为单号/标题、申请部门、申请人、需要日期；更多条件包含法人、品类、优先级、分配情况。

列表列：需求单号/标题、申请人/部门、需要日期、估算金额及完整性、审批状态、采购安排进度、异常、操作。采购安排显示“已安排 3/5 行”，不能把吨和件相加。

详情摘要包含申请用途、法人、负责人、审批、当前版本。Tabs 为需求明细、采购安排、审批与变更、附件、单据流。明细区同时展示授权量、分配到计划、直接下单、待审批占用、未安排量；供应商建议显示来源，不用强约束标签。

主操作：草稿编辑/提交；审批中查看/撤回；已批准且未完全安排时进入需求池；已批准调整走新版本。已有下游时不能删除明细或减少至已占用以下。需求已经全部下单只能称“采购已安排”，不能称“需求已满足”。

### P03 需求编制

页面类型：独立页面，复用可编辑明细表；单行快速新增可以是同一编辑器的轻量模式，不另写业务规则。

头部字段：需求标题、法人、申请部门、需求人、用途、优先级、期望采购时间。行字段：货物/服务、编码或描述、品类、规格/范围、数量与单位或授权金额、需要日期、交付地点/使用部门、服务期间、验收要求、估算及价格口径、建议供应商、附件。

建议供应商始终非必填；可以选择目录供应商，或录入候选名称和建议理由。未准入候选标“建议信息”，不可自动变成正式订单供应商。

草稿允许估算、供应商和部分计划信息不完整。提交必须有可识别内容、申请用途、责任归属和可控制的数量或金额。数量型需求可未估价提交，由企业策略决定是否要求补价；金额型需求必须有明确授权金额及口径。

### P04 需求池与汇总

页面类型：明细工作台。仅可选择已授权且有未安排余额的需求行；显示组织、规格、需要日期、可用量、估算、建议供应商、现有占用。

操作为“编制采购计划”和“直接编制订单”，后者按策略显示可用性。选择可跨多张需求，但不得跨无权限组织。点击“汇总预览”后展示分组依据、预计生成计划数/行数、每条原始需求分配、本次量及转后剩余。

合并必须核验法人、采购对象、规格、计量方式和单位。不同需要日期、地点可以保持为独立来源份额，不取第一行覆盖；不同法人拆单；无法确认等价单位的行不合并。手动拆开允许，强行合并不兼容行禁止。

首期一次可以预览多个分组，但每张计划分别形成草稿、独立提交。结果页展示已创建和未创建项，重试复用原请求身份，不能误称全部成功。

### P05 采购计划列表 编制与详情

页面类型：列表＋独立编制/详情。支持来源需求、独立编制两种入口；计划内允许部分来源行、部分独立行，但同一行不混合“有来源”和“无来源”的量。

头部字段：名称、法人、采购组织/组、负责人、计划下单日期、目标交付日期、采购方式、计划说明。明细字段：对象/规格、计划量/金额、单位/币种、估算及依据、需要日期、交付地点、建议供应商、来源分配。

独立行填写采购依据和授权量，提交后按同样审批处理；不虚构需求单。计划估算未知则显示“已估价金额＋未估价行数”，不显示具有误导性的全额合计。

详情 Tabs：计划明细、来源需求、已编订单、审批与变更、附件、单据流。可用量旁显示“已批准转单”“审批占用”“当前可转”。已批准计划可分次、分供应商编制订单。取消计划只释放没有下游占用的部分；有订单时给出依赖清单。

### P06 统一采购订单编制

页面类型：独立页面，是本次重点改造。原计划详情 820px 抽屉不再承担订单正式生成。直接新建、需求转单、计划转单、外部依据转单共用该页面。

组织为三个可回看的步骤：选择来源及本次采购范围 → 完善商业与交付条件 → 核对并保存/提交。直接新建默认从第二步开始。生成的是可审查的草稿，不会因从计划进入就自动批准。

| 区域 | 必须展示/填写 | 编辑规则 |
| --- | --- | --- |
| 来源条 | 来源单号、版本、原需求日期、建议供应商、拟生成订单数 | 原始内容只读；可修改本次选取范围 |
| 订单头 | 法人、采购组织/组、采购员、实际供应商/站点、币种、订单日期、付款/交付条件 | 有可靠默认值时带出；正式提交确认适用条款 |
| 明细商业表 | 采购内容、规格、可转量、本次数量/金额、单位、成交单价、计价基数、税、未税/含税金额 | 实时计算，来源估算与成交信息分开展示 |
| 行详情 | 来源分配、交付安排、服务范围/期间、业务归属、验收要求、商业依据 | 分组展开，不把全部字段摊成超宽表 |
| 校验面板 | 阻断、需审批例外、提示，定位到字段/行 | 缺失价格、超量、过期依据、延期等明确分类 |
| 固定底栏 | 当前草稿金额、对应范围估算、价格差异、保存草稿、提交审批 | 合计始终可见；不把关键信息隐藏到横向滚动外 |

默认桌面列集控制为：内容、可转、本次、单价、税率、含税金额、要求交期、校验。物料号和单位放内容/数值副行；未税金额、税额及详细条款在行展开及合计区显示。使用“商务/交付/来源”列视图切换，核心采购内容和操作固定。

供应商不相同的行拆成不同订单；同法人、供应商/站点、币种及商业条件兼容才可同单。预览左侧展示订单分组，右侧编辑当前组；每张订单独立提交，组间失败不撤销已成功订单，也不能重试时重复创建。

原始需求、计划不会被下游改价、改交期覆盖。实质性规格替代不当作修改描述，首期需调整来源或重新授权。独立增加的采购内容单列并说明直接采购依据。

### P07 订单列表 详情和变更

列表常用筛选为订单/SAP 编号、供应商、采购员、单据状态；更多条件为法人、约定交期、来源和 SAP 状态。Tabs 用“全部、待审批、待生效、待执行、执行中、履约关闭、异常”，避免把所有状态揉在一个字段。

列表首先展示业务单号，SAP 号为副标识；无 SAP 号的草稿仍有稳定入口。字段包括供应商、采购组织、订单日期、约定/预计金额、限额上限提示、审批、履约、交期风险、SAP、操作。

详情顶部：正式版本、当前变更、供应商、法人、币种、约定金额/预计金额与上限、关键阻断原因。Tabs：订单明细、交付安排、履约记录、来源与商业依据、变更与审批、附件、单据流、SAP 信息。

“编辑”仅针对工作草稿；“发起变更”针对正式订单。变更页展示原值/新值/差异和执行影响。首期已执行行不直接改供应商、采购对象、单位或既往价格；新增或调整未执行部分，必要时取消剩余后另起新行/新单。

一个正式订单最多一个在途变更。变更涉及的行设变更锁，禁止新的收货/验收提交；已有审批占用和 UNKNOWN 先处理。未受影响行可继续执行。批准后直到 SAP 确认前，仍以原正式版本展示承诺；新版本生效后按正式交付安排重新计算未交量与交期风险；内部预计信息若来自旧版本，仅作历史参考，不自动当作新版本有效数据。

### P08 订单交付信息（嵌入订单详情）

页面类型：订单详情“交付安排”Tab／行展开区，不是独立业务模块。跨订单的临期、逾期筛选复用订单列表和履约工作台，不另建供应商确认或催交工作台。

展示订单行、交付批次、约定交期、交付数量/金额、地点、净履约、未履约、关闭量与风险。货物显示数量和单位；服务显示服务期间与适用的数量/金额，不强制套用“到货”。

采购员可选填写最新预计到货日期、延期原因、补充说明；复用现有操作记录和附件，不要求逐次登记电话、邮件、联系人或回执。预计日期可以为空，页面明确标注“内部预计（非供应商确认）”，显示记录人及更新时间。旧版记录保留，不自动覆盖当前版。

约定交期属于正式订单版本；预计日期仅是运行备注。延期或逾期判定仍以当前正式约定交期和有效未履约量为准，不能通过推迟预计日期消除逾期。分批交付逐批计算；全部履约或已关闭部分不再产生新的待交提醒。预计日期更新不发送 SAP 订单变更，也不改变可收/可验余额。

改变正式数量、价格、地点或约定交期仍走受控订单变更。沟通附件仅作依据，不直接改变生效订单。详细存储见数据库第 6.2 节。

本期不增加“未登记供应商回复就不能收货”的校验，也不伪造“已接受”。企业已有审批、订单生效、SAP 释放及外部执行资格要求继续由权威规则校验，未满足时仍然阻断。

### P09 采购履约工作台

页面类型：统一订单行工作台。保留四类核心动态动作，不增加物料收货、服务收货等重复主菜单。

首屏列：PO/行、供应商/采购内容、场景、订单量/额度、已确认、待审批占用、当前可执行、最近交期、进度/风险、操作。需要时展开交付批次；数量型行带单位，金额型行带币种及口径。

快速筛选：全部可见、待执行、部分执行、即将到期、超期、受阻。受阻可看到草稿/未生效等原因，但默认待执行视图只显示有效资格行。不同入口使用同一动作资格接口。

操作资格至少核验：组织和动作权限、正式版本、审批、SAP PO 就绪与释放条件、场景支持、冻结/关闭、变更锁、有效余额。未知场景不显示“收货”。单行某笔请求 UNKNOWN 不应冻结无关订单；本行需防重复和余额超用。

### P10 四类动态履约

| 场景 | 载体 | 本次输入 | 关键规则 |
| --- | --- | --- | --- |
| 库存/消耗性货物 | 800～880px Drawer；多批次复杂业务转独立页 | 数量、业务日期、过账日期、地点、条件批次、送货单、附件 | 订单上下文只读；批次启用时必填；单位换算有据可查 |
| 无编码货物 | 同一 Drawer、不同 Schema | 描述只读、数量/单位、收货日期、交付地点、接收结果、附件 | 不出现强制物料选择器；NON_STOCK 不套库存必填 |
| 服务 | 独立页面 | 服务期间、工作量或金额、成果说明、验收人、结果、证据 | 按量服务数量与金额均校验；固定价服务按金额；不通过不累计验收 |
| 限额服务 | 简单单项 Drawer；多项明细使用服务页面 | 实际内容、服务日期、工作量/单价（适用时）、确认金额、结果、依据 | 预计值预警、上限阻断；审批占用计入可用额度 |

共用分组：订单上下文 → 余额及处理中情况 → 本次业务 → 附件与说明 → 折叠 SAP 信息。底部为取消、保存草稿、确认/提交验收；有审批时文案必须是提交，不能说已验收。

货物本期使用简化接收结果“接收/拒收”；专业检验和质检库存不模拟。拒收仅登记事实并建立异常，不生成正向收货事件。部分接收以本次实际接收数量确认，并单列拒收说明，不能把整批都记为成功。

服务验收本期仅“通过/不通过”，不启用含义不明确的“有条件通过”。已确认错误金额走服务更正，不能使用采购退货。服务证据可登记多附件；首期不做多人会签及里程碑完成百分比自动计量。

提交成功反馈示例：“收货单 GR… 已确认，SAP 待处理”，提供查看单据和继续收货。刷新后正式记录仍可查询；失败信息留在表单，不仅弹一条短暂提示。

### P11 履约记录和退货与更正

履约记录按事实类型筛选，显示原订单/行、业务时间、数量/金额、业务状态、SAP 状态和原/反向关联。详情保留原输入、审批、附件、集成结果及后续处理。正向记录被冲销后仍存在，汇总时用正反事件相抵，不能删除正向量再减一次。

退货与更正页分为采购退货、收货冲销、退货冲销、服务更正；不同主操作进入不同标题与文案的表单。

| 动作 | 关键输入和影响预览 | 首期限制 |
| --- | --- | --- |
| 采购退货 | 原收货行/批次、历史已退/已冲、待处理、当前可退、本次量、原因、是否补货、退货日期 | 支持部分；校验原记录净额和权威依赖；真实退货证据不能缺 |
| 收货冲销 | 原单、数量、SAP 凭证、错误原因、日期、反向后的余额 | 默认按适配器支持的完整执行行/凭证粒度，不开放未经适配的任意部分冲销 |
| 退货冲销 | 原退货、可冲销范围、原因、对净收货和补货义务的影响 | 已有依赖补货/变更时先处理依赖，不盲目恢复 |
| 服务更正 | 原验收、金额/期间、原因、下游依赖 | 未生效可撤回；已生效新增反向更正，之后重新验收 |

二次确认列明单号、数量/金额、影响、原因。原记录有冲销/退货在途占用或下游不明，解释阻断。非幂等重复点击不生成第二笔业务。

“不需要补货”形成关闭/变更任务，并暂时阻断相应退回量被再次收货。必须选择未满足需求的处置：仍需另行采购，或业务已经不再需要。前者在正式减量后释放来源到原计划/需求；后者再经授权关闭相应来源余额。退货本身不自动替采购员作出这个决定。

### P12 业务异常与履约关闭

异常类型首期限定：来源余额冲突、订单资料待补、交付延期/逾期、收货差异、验收不通过、反向依赖受阻、SAP 失败/未知/不一致、场景待识别。

列表显示业务对象、问题、严重性、责任人、期限、状态、下一步。详情显示事实依据、处置记录和建议操作。由业务命令产生修复结果，不能点击“已解决”就改订单量或 SAP 成功状态。

重复检测同一异常更新原活动任务，不不断创建新任务。关闭须有实际处置或经授权接受偏差的原因；接受偏差不表示双方数据一致。

履约关闭区分：足量完成、短交关闭、取消未执行部分。显示实际已收/验收、未履约、已关闭量及原因。尚有审批占用、未知任务、未完成退货、更正或在途变更时不允许静默关闭。这里只关闭本期执行责任，不宣称发票、付款、质保已结束。

### P13 SAP 执行监控和一致性核对

监控列表沿用现有页面，补齐业务请求 ID、业务版本、任务动作、ERP 状态、凭证、错误摘要与允许操作。业务单据状态、集成任务状态分列。

UNKNOWN 的主操作为“核对 SAP 状态”；只有取得明确未执行证据且适配器允许安全重发时，才提供重试。业务请求身份不变，调用尝试单独编号。无法建立可靠防重机制的接口进入人工核对，不承诺绝对自动恢复。

一致性核对支持本地有业务无 ERP 结果、ERP 有凭证本地未关联、数量差异、外部已冲销、PO 变更/关闭未同步。处理后保存证据和复核结果。普通人员只看到可理解的原因；报文按权限脱敏折叠。

### P14 执行配置

执行场景回答“适用什么语义、什么动作、怎样控制”；动态字段回答“动作中的字段如何显示和校验”；采购策略回答“某组织/采购方式需要哪些前置、审批、容差与订单生效条件”。三页引用同一发布版本，不能三个页面各存一套 local state。

| 页面 | 编辑内容 | 不允许编辑的内容 |
| --- | --- | --- |
| 执行场景 | 名称、受支持属性组合、识别条件及优先级、允许动作、控制方式 | 未实现动作不能靠配置启用 |
| 动态字段 | HIDDEN/DISPLAY/OPTIONAL/REQUIRED/AUTO、默认来源、受限条件及提示 | 不能移除核心余额校验、原单关联或事实字段 |
| 采购策略 | 前置需求/计划/外部依据、审批链、允许直接采购、容差、临期提醒阈值 | 不预置对话中举例的 50 万门槛；不新增供应商确认门槛；不运行任意脚本 |

保存草稿 → 样例预览 → 冲突检测 → 发布 → 生效范围。界面同时说明“当前编辑草稿”和“线上生效版本”。相同范围同优先级冲突阻止发布；无匹配不能默认库存收货。回退通过发布新版本实现，不重写历史。

## 8 字段来源和校验矩阵

### 8.1 关键字段继承

| 字段 | 需求/计划阶段 | 编制订单 | 正式订单/履约 |
| --- | --- | --- | --- |
| 原单号/行/版本 | 系统生成 | 只读引用 | 始终保留 |
| 物料编码 | 可空 | 继承或有效目录选择 | 只读；非全局必填 |
| 采购描述/规格 | 必须能识别需求 | 可补充；实质替代重新授权 | 不改写原交易对象 |
| 建议供应商 | 可空，可文本 | 提供候选，不强制采用 | 作为来源说明 |
| 实际供应商 | 不必确定 | 提交前有效且满足映射 | 已执行后不能直接换 |
| 本次数量/金额 | 来源授权量 | 可部分转出，不超可用 | 执行不超有效上限 |
| 估算价格 | 数量需求可待补 | 保留参考，不冒充成交 | 仅用于同口径比较 |
| 成交价格/税口径 | 非必要 | 必须确认适用值 | 首期不追溯改写已执行价格 |
| 需求日期/要求交期 | 原期望 | 可提出调整并解释偏差 | 正式交期变更留版本；内部预计另存，不覆盖约定 |
| 使用部门/项目 | 申请归属 | 保留分配，可按权限补齐 | 执行继承，不重填会计科目 |
| SAP 技术字段 | 不展示 | 后台映射 | SAP 信息区只读 |

### 8.2 按场景提交订单的最低完整性

| 场景 | 必须具备 | 不应强制 |
| --- | --- | --- |
| 库存货物 | 可用物料主数据、规格、数量/单位、价格/计价单位/基数、税口径、交期、工厂及有效库存管理上下文 | 每次重新输入 SAP 会计归属 |
| 无编码非库存货物 | 描述、品类、规格、数量/单位、价格、税口径、交付地点/接收人 | 物料编码、库存批次 |
| 按量服务 | 范围、期间、数量/单位（如月/工时）、单价、金额、验收依据和责任人 | 库存地点 |
| 固定价服务 | 范围、期间、约定金额及口径、验收依据和责任人 | 虚构数量和单价 |
| 限额服务 | 范围、有效期、预计金额、上限、币种/税口径、确认责任人 | 把上限自动当预计支付金额 |

库存管理确实要求物料编码时属于该场景条件，不与全局物料可空冲突。无编码货物不应假装可直接进入需要物料主数据的库存账。

### 8.3 错误级别

- 阻断：无权限、超授权量、缺必需商业信息、未知场景、过期版本、未知外部依赖。
- 需审批例外：允许范围内的超估算、调整交期、策略允许的偏离。提供原因与依据，不能当场绕过。
- 提示：建议供应商未采用、接近上限、存在较早需要日期。能继续，但保留可见信息。

隐藏字段如果不适用，不提交脏值；只读继承字段由服务端重取或核验，不相信客户端传来的权威值。服务期间起止、限额预计值≤上限、日期有效性、按量服务金额计算均为跨字段校验。

## 10 通用 UI 规范与组件复用

- 1440×900 为设计基准，兼容 1280/1366/1920；窄屏折叠筛选和侧栏，表格内部滚动，不让整个页面横向溢出。
- 继续使用 `src/app/theme.ts` 的企业蓝、深蓝导航与语义状态 Token；绿色成功、蓝色进行中、橙色待办/预警、红色失败、灰色关闭。状态带文字，不只用颜色。
- 标题 20～24px、正文 14px、辅助文字至少 12px；间距采用 4/8 倍数。数值右对齐、数量带单位、金额标明币种和税口径。
- 列表固定单号/采购内容和操作；不能固定太多列挤掉中间数据。复杂编制不在窄抽屉内堆 15 列。
- 主操作不超过两个高强调按钮；危险操作放二级菜单并确认。不将普通审批、查询等全部做成红色。
- `PageHeader`、`MetricStrip`、`StatusTag`、`PageState`、`DynamicForm`、`DocumentFlow` 优先演进复用。新增 `SourceAllocationEditor`、`CommercialLineEditor`、`RevisionDiff`、`ActionAvailability`、`AttachmentPanel`、`ValidationSummary`，避免按入口复制页面。
- 每个页面均有 Loading、Empty、Error、No Permission、Partial；失败保留筛选和编辑值。数据过期时显示刷新时间和不可提交原因。
- 表单支持键盘、明确焦点、字段标签、定位首个错误；图标按钮有文字说明。离开未保存内容要确认；草稿恢复须有真实数据来源。
- 附件上传成功才产生可提交附件 ID；有失败、重试、下载和权限。浏览器原型仅本机持久化时明确告知，不假装跨用户已共享。

## 14 建议评审采用的默认决策

本次已经按以下默认值形成完整方案，不需要先逐条回答才能阅读：计划环节可选且支持独立创建；单法人单据；SAP 为正式订单权威；本地编制与审批后请求 ERP 生效；订单交付信息纳入核心，供应商确认流程暂缓；合同与寻源只引用；金额采用明确税口径；复杂资产/里程碑/寄售/委外本期不启用。

本轮已确认的范围调整是：暂缓供应商确认，保留订单交付信息；数据库统一 pur_ 表前缀且不设置物理外键。其余默认值仍为设计建议，不代表已经获得全部核心模型变更的实施批准。客户 SAP 接口实际能力、审批归属以及反向粒度应在实施前确认。若与现有 ERP 不一致，调整适配配置及受影响设计，不以假成功掩盖限制。
