# Skill: Enterprise UI

## 目标

为采购执行中心生成稳定、专业、高信息密度、易操作的企业级后台页面。优先保证业务效率、信息层级和一致性，不追求炫技视觉。

## 适用场景

当创建或修改以下页面时使用：

- 列表页
- 详情页
- 工作台
- 配置页
- 抽屉表单
- 审批/确认页
- 监控页

## 默认技术偏好

- React + TypeScript
- Ant Design 作为主要组件体系
- 使用 Design Token 统一主题
- 图标优先使用 Ant Design Icons
- 复杂表格逻辑可结合 TanStack Table
- 路由优先 React Router 或项目既有方案

不要无必要引入第二套大型 UI 组件库。

## 页面整体框架

PC 优先，默认设计基准 1440 × 900。

结构：

```text
顶部栏
├─ Logo / 系统名称
├─ 当前组织（如需要）
└─ 用户区域

左侧导航
└─ 一级/二级业务菜单

主内容区
├─ Breadcrumb
├─ Page Header
├─ 状态/摘要区
├─ 查询或主操作区
└─ 核心业务内容
```

## 列表页规范

默认结构：

```text
页面标题 + 简短说明 + 主要操作
快速状态筛选
查询条件
业务表格
分页
```

原则：

- 查询条件默认 1~2 行，避免占据过多首屏。
- 常用条件直接显示，低频条件放“更多筛选”。
- 主要操作不超过 2 个高强调按钮。
- 表格是主角，不要用大量卡片挤占首屏。
- 状态筛选用 Tabs、Segmented 或轻量计数项，不使用大型 KPI 大屏风格。

## 详情页规范

默认结构：

```text
返回入口
业务主标题 + 状态
关键摘要信息
核心操作
Tabs
```

Tabs 推荐：

- 基本信息
- 明细
- 履约记录
- 单据流
- 附件
- SAP信息（如适用）

关键上下文必须在页面顶部持续可见：

- 单据号
- 供应商
- 当前状态
- 核心金额/数量

## Drawer / Modal 使用原则

优先使用 Drawer：

- 收货
- 简单退货
- 简单冲销
- 快速查看明细
- 编辑少量字段

使用独立页面：

- 服务验收
- 多附件、多明细业务
- 复杂配置
- 多步骤处理

Modal 仅用于：

- 二次确认
- 高风险动作确认
- 简短选择

不要把复杂业务塞进小 Modal。

## 状态设计

统一状态语义：

- 绿色：完成 / 成功
- 蓝色：处理中 / 执行中
- 橙色：待处理 / 预警 / 即将到期
- 红色：异常 / 失败 / 阻断
- 灰色：关闭 / 作废 / 未启用

同一状态在全系统必须保持同样颜色和文案。

## 信息密度

- 列表页：中高密度
- 详情页：中等密度
- 配置页：高密度但分组清晰
- 不用超大字号展示普通业务数据
- 数值要支持千分位、金额格式化、单位跟随

## 表单布局

- 一般表单使用 2 列布局
- 长文本、附件、说明独占一行
- 数量、金额、单位靠近展示
- 只读字段使用弱化视觉，不与可编辑字段混淆
- 必填符号只用于真正必填字段

## 禁止事项

禁止：

- 大面积渐变
- 玻璃拟态
- 霓虹科技风
- 无意义插画
- 大量悬浮卡片
- 所有内容都包一层 Card
- 过量阴影
- 用颜色替代所有文字状态
- 页面中出现多个风格不同的按钮体系

## 输出前检查

每次生成页面前确认：

1. 当前页面主要业务任务是什么？
2. 用户完成任务需要最少几步？
3. 首屏是否能看到核心单据和状态？
4. 主操作是否突出？
5. SAP 技术细节是否污染业务页面？
6. 是否存在不必要的大卡片或装饰？
