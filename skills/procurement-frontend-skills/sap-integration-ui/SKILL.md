# Skill: SAP Integration UI

## 目标

规范采购执行中心与 SAP 集成相关的前端表现，使业务用户看到的是业务语义，技术用户又能获得足够的排错信息。

## 核心原则

业务前台不要围绕 SAP 技术字段设计。

业务用户关心：

- 是否成功
- 是否已过账
- SAP凭证号
- 为什么失败
- 下一步怎么办

技术用户才关心：

- Item Category
- Account Assignment Category
- Movement Type
- BAPI/API
- Request / Response
- 技术错误码

## SAP信息分层

### 业务层默认展示

- SAP采购订单号
- SAP行项目
- SAP同步状态
- SAP执行状态
- SAP物料凭证号（如有）
- 服务确认号/SES（如有）
- 友好错误摘要

### 技术层折叠展示

- Document Type
- Item Category
- Account Assignment Category
- Movement Type
- Fiscal Year
- SAP技术错误码
- 请求ID
- 原始返回信息

## 财务科目边界

业务前台原则上不显示、不维护：

- GL Account
- 库存科目
- 费用科目
- GR/IR
- 借方/贷方科目
- 成本要素

如果接口排错需要查看，可放在技术详情中，只读。

成本中心、WBS、资产等：

- 若具有业务语义，可以“业务归属”展示
- 若只是 SAP 技术上下文，则隐藏或只读
- 默认继承原 PO，不要求收货人员重新录入

## SAP状态

统一状态：

- WAITING：待发送
- PROCESSING：处理中
- SUCCESS：成功
- FAILED：失败
- UNKNOWN：状态未知

UI 文案：

- 待发送
- SAP处理中
- SAP执行成功
- SAP执行失败
- SAP状态待核对

UNKNOWN 必须使用橙色高风险提示，不能直接显示“失败”。

## UNKNOWN状态处理

场景：

SAP可能已经成功，但业务系统超时未收到结果。

页面必须提供：

- SAP状态核对
- 查看请求信息

不要直接提供醒目的“重新执行”主按钮。

避免重复过账。

## SAP执行监控页

推荐列：

- 业务单号
- 业务动作
- SAP PO
- Item
- 执行时间
- 状态
- SAP凭证
- 错误摘要
- 操作

操作：

- 查看业务单据
- 查看SAP详情
- 状态核对
- 重试（仅确认可重试时）

## 错误展示

先翻译为业务语言。

例如：

推荐：
> SAP过账失败：库存地点1001不允许该物料收货。

技术详情：
> M7 xxx / ...

不要把原始技术报文直接作为业务主提示。

## SAP详情 Drawer

推荐分组：

1. 业务信息
2. SAP凭证
3. 请求状态
4. 技术信息
5. 请求/响应（管理员可见）

## SAP动作映射

业务页面只显示：

- 采购收货
- 收货冲销
- 采购退货
- 退货冲销
- 服务验收

不要让普通用户输入：

- 101
- 102
- 122
- 123
- BAPI名称

## 对账页

支持以下异常类型：

- 本地成功，SAP无凭证
- SAP成功，本地无结果
- 数量不一致
- SAP已冲销，本地未更新
- PO已关闭，本地仍可执行
- PO已变更，本地未同步

异常列表必须有明确“处理建议”。

## 权限

普通用户：

- 看业务状态
- 看SAP凭证号
- 看友好错误

接口运维：

- 看技术字段
- 看错误码
- 状态核对

管理员：

- 看原始报文
- 重试
- 手工对账处理
